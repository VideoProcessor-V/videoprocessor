### 2a. Non-net upscale path = Stage 8b (owner requirement, added to N9)

Under the owner's later direction (section 2b) 8b is not only the fallback: it is always the upscale, and the net
refines its output. Points (a)-(d) still hold; (a) is now decided in favour of (ii).

Wherever B-refine cannot run (rate over budget, laptop, nets off, fingerprint mismatch, not trained), the output is
exactly **Stage 8b** (adaptive upscale blend, `AdaptiveDownscaleStage` upscale form, `docs/VP-stage8b-upscale-blend.md`):
CNN doubler (FSRCNNX/ArtCNN + SSimSuperRes) blended per pixel with `ewa_lanczossharp` (anti-ringing) by the
motion-compensated grain map from trusted vectors.

(a) **Route when B is bypassed.** Two candidates: (i) route_4k classical 1-D x2 to 4K at the entrance, then the
Stage 8 hybrid downscale to 1600p; (ii) no route_4k: processing stays at the encoded size and 8b upscales in the
main render (doubler to 2x, linear-light downscale 2x -> 1.48x for 1080p; for 1440p doubler to 2880 then 1.8x down,
or the plain kernel at 1.11x). Recommendation: **(ii) direct 8b** as the default fallback. It is more faithful
(grain-aware CNN/kernel blend vs a plain Lanczos x2, one resample to output instead of x2 then down) and cheaper
(every entrance stage, deband, texture restore, motion and D's source branch stay at 1080p/1440p instead of
4K/2880p). It also keeps the 1440p "doubled per axis" rule (the doubler is the x2). Note D does not apply on this
route (no output downscale; D shows "bypassed: upscale via Stage 8b"). Confirm in package N9-P0b: chain timing on the
3090 and a quality compare on the kit's eval clips (grain RMS gate, edge MTF) for (i) vs (ii) at 1080p and 1440p,
plus 1440p doubler vs plain 1.11x kernel.
(b) **Coverage check** (in P0b, code + tests): 8b's gate is height-only (`source height < output height`):
a width-only upscale (anamorphic squeeze with height at or above the output) is not covered: change the gate to
"either axis upscaled". The doubler is two-axis: on a one-axis upscale it doubles both and the kernel scales one axis
back down 2x (correct but wasteful); the faithful branch's 2x2 average requires an exact 2x prescale of the crop; other
ratios are "not applied" (`AdaptiveDownscaleStage.cpp:139` status string): verify that line reaches Ctrl+I/Config
status (no log-only). Tests to add: anamorphic fit (V factor > H), one-axis upscale, 1440p, odd crops, A-lens/NLS.
(c) **Improvements to be a worthy fallback** (package N9-P12, after P0b): 1. motion-compensated temporal stabilisation
of the CNN residual (CNN - faithful), reusing `repair/texture_restore/DetailPulse` logic (warp last residual by
trusted vectors, bounded blend on textured non-grain areas, vector-validity fallback, grain never averaged): 4-5 h;
2. either-axis gate + one-axis path (kernel-only on the 1:1 axis): 1 h; 3. 50/60p grain map from the low-latency
backward vectors (today the matcher runs only <= 30 fps, so 60p falls to the per-frame scalar): 2 h; 4. visible
status lines: 0.5 h. Total **7.5-8.5 h, ~0.8M**, O (S tests). Byte-identical when 8b is off.
(d) **Visible bypass reason**: `NetBypassSet` entry and Ctrl+I/Config status/Ctrl+Alt+D/one-time notice, e.g.
"Upscale: Stage 8b (B bypassed: 14.8 ms > 11 ms allowance at 30p)", "... (B: 1440p input over budget)",
"... (B: fingerprint mismatch: rebase_mode)", "... (B: not trained)", "... (nets off: laptop profile)". Part of P8.

### 2b. B-refine (owner direction 2026-10-26; supersedes plain B and the route_4k B wiring in plan-n9)

The upscale net is a **residual refinement on top of Stage 8b's output** (the same pattern as D on the hybrid
downscale): `out = 8b + bounded residual`. Net off or bypassed = exactly 8b (byte-identical; tested). Plan-n9's B
(x2 net replacing the upscale, B_h/B_v at the entrance, route_4k stage, r16 hand-off) is superseded; the
`scaling.route_4k` slot stays a held placeholder. Design consequence to tell the owner (not a blocker): "always-4K
processing" for upscaled sources now lives inside 8b (doubler to 2x, then the linear-light downscale); entrance
stages keep running at the encoded size, which is also the cheaper and grain-safer choice.

**(1) Does 8b support per-axis-only upscales today?** Partly.
- Gate: height-only (`source height < output height`) -> width-only upscales are missed. Fix: either axis.
- CNN branch: FSRCNNX/ArtCNN are fixed 2x on both axes (hook LUMA). On a one-axis upscale they double both axes and
  the kernel scales the 1:1 axis back down 2x: works, but the CNN then invents detail on an axis that was never
  upscaled (grain rule risk) and costs a full doubler. Needed: **CNN branch off for one-axis upscales** (visible:
  "8b: faithful only (one-axis upscale)"); the detail on that axis comes from B-refine's one-axis variant.
- Faithful branch: `ewa_lanczossharp` is polar; at 1:1 on one axis a polar filter is not identity (it softens that
  axis). Needed: for one-axis upscales use a **separable (orthogonal) Lanczos-3/sharp kernel** on the upscaled axis
  and leave the other axis untouched (libplacebo's separable `lanczos` path or VP's 1-D kernel from SourceRebase);
  anti-ringing kept, no clamp (BTB/WTW).
- Faithful-behind-doubler 2x2 average requires an exact 2x prescale of the crop; anamorphic two-axis upscales with
  different factors are fine (kernel is per-axis after the doubler). Tests: one-axis H, one-axis V, anamorphic
  (V > H), 1440p, odd crops, A-lens/NLS.
- Effort: folded into N9-P12 (now 9.5-10.5 h, ~0.95M: +2 h for the separable one-axis faithful path and the
  CNN-off rule). P12 moves **before** B-refine wiring and should land before WP-20 if lane time allows (8b is a
  shipped stage; the fixes are visible behaviour changes that WP-20 should cover).

**(2) B-refine: inputs, labels, cost.**
- Inputs (luma): 8b's output at the output grid (primary); a source-grid branch from the re-based encoded luma
  (1080p/1440p, the D source-branch pattern, 1 -> 8 -> 8 ch); per-axis scale factors as two scalar conditioning
  inputs (or per-variant nets: both-axes, H-only, V-only; the kit picks after a quick compare). Optional: 8b's grain
  weight map (alpha), so the net knows where 8b leaned to the kernel.
- Labels: 4K masters through VP's faithful hybrid downscale to the same output size (what a native 4K source gives
  through VP). Inputs: the same masters degraded per axis (1080/1440 per axis, real codecs as the kit does), then
  **rendered through VP's harness** (`tools/vp-scale-render`, real re-base + 8b at the default 8b settings, motion
  on so the grain map is real). Variants per doubler (FSRCNNX vs ArtCNN), SuperRes on/off, `upscale_light`: the
  fingerprint records 8b's settings; a mismatch bypasses visibly ("B-refine: 8b settings differ from training:
  doubler"). Train the default 8b settings first; others later.
- Output: bounded residual `tanh(x) * bound` (as D), grain gate, fp32.
- Cost estimate (D_small-class trunk at the output grid ~6.5k MAC/px + source branch 864 MAC per source px):
  1080p -> 2560x1600: 26.6 + 1.8 = **~28 GMAC** (3090 floor 1.6 ms, fused ~4.0 ms, V2 ~2.9 ms; laptop fused ~22 ms);
  1440p -> 1600p: 26.6 + 3.2 = **~30 GMAC** (floor 1.7, fused ~4.2, V2 ~3.1); with a half-res trunk (round 3):
  **~8-10 GMAC** (3090 V2 ~0.9-1.0 ms; laptop V2 ~5-6 ms). Compare plain B: 107 GMAC (1080p) / 191 GMAC (1440p).
  Plus 8b itself (doubler + SuperRes; already in today's chain, measured in P0b).
- Seat: the same `AdaptiveDownscale::Blending` seat item 10 adds for D (upscale form vs downscale form; D and
  B-refine are mutually exclusive per frame by construction). Runs inside `pl_render`, so per refresh unless the
  warp/repeat-reuse covers it (same rule as D, A5).
