## X5 cut A/B (FIX-X5-CUT-P4)

The owner requires a GPU before/after of the grain-term cut before x5dup lands. Since 2026-11-15 (owner-intent fix) the A/B counts FALSE cuts as well as missed cuts: a false cut is equally unacceptable.

- Capture: `X5AbCaptureTests.inl` (included by `AdaptiveScalingOneAxisMotionTests.cpp`). It does nothing unless `VP_X5AB_LIST` is set, so a pass without that variable is not evidence of anything and is never cited. Both sides run the same `.inl` text; the before branch must carry the commits that added the `cut_state` and `cut_here` / `confirmed` / `cut_late` columns (the scorer refuses a CSV without them).
- Clips: `tools/x5ab-extract.ps1` (default `-Set cuts`) makes the cut set: `cut` (a splice at frame 60), `flash` (+64 codes on frames 60-61), `pan` (one still frame panned, no cut) and `fade` (one still frame faded to black and back, no cut). It writes `x5ab-list.txt` and, only when absent, the truth template `x5ab-truth.txt`.
- Truth: hand-marked. `pan` and `fade` are `synthetic` (no cut by construction). `cut` and `flash` are live footage and start `UNMARKED`: a person watches them, confirms the splice, adds any real cut inside either clip and sets `marked:<who>:<date>`. The scorer refuses UNMARKED lines. The truth file is data and is never overwritten by the script. No clip pixels are committed.
- Run each side under GPU-QUIET on the same adapter (`VP_TEST_GPU=hardware`, `VP_X5AB_LIST`, `VP_X5AB_OUT`, `VP_X5AB_SIDE=before` or `after`; clear the CSV first, the harness appends), then `tools/x5ab-score.ps1 -Out <dir>` (it reads `x5ab-list.txt` for the frame counts). Never cite a score produced before C5's MUST 2 commit.
- After side (C5, audit x5dup MUST 1/2): the harness takes the module's cut from the SCENE PRODUCT: U7's `CutTracker` over the clip's P4 records, groups sealed and delivered as `SkeletonModule::FillScene` delivers them for contiguous frames (a confirmed cut goes out once, with the next frame's group: `cut_late=1`), read by the production rule `AdaptiveDownscale::VerdictFromScene` (`cut_rule=u7_scene`). The CSV also logs the frame's own verdict (`cut_here`, `confirmed`, final when the clip ends). The real stage with the skeleton store bound is still gate B-S3.
- Report, per clip and per side: missed cuts, false cuts (total and per minute), recall and precision against the truth list, and the grain-term snaps with their frames (every CSV row is one advance, so `cut=1` is one snap; the definitional first-frame snap, `cut_state=first`, is counted as a snap but never scored as a cut). The after side is scored at the scene product's own cut frame (a late snap minus `-AfterDeliveryOffset`, 1 in the harness), which must carry a confirmed `cut_here`; every confirmed `cut_here` must have been delivered.
- No vacuous pass: the run fails on an empty CSV, a case missing from the list, the truth or either CSV, any of the kinds `cut`, `flash`, `pan`, `fade` absent, rows that are not exactly frames 0 .. N-1 of the list line (the harness also fails a short clip), a `cut` line without a truth frame, after rows not `u7_scene` with `first` / `known`, or before rows not `meanstep20_derived` / `derived`.
- Pass rule (after side, every clip): zero false cuts, zero missed truth cuts, recall and precision >= 99.5 % where defined, no Unavailable or unasked frame.
- A false cut on the after side is a defect of the SHARED U7 law (`CutFadeJudge::CutTracker`, the skeleton's scene product): report it to U7-ACCURACY. Never fix it with an x5dup-local threshold or veto (one copy; no private detector).
- These 5-second clips are a per-clip A/B, not the U7-ACCURACY recall/precision >= 99.5 % gate.
- The `__has_include` / `X5AB_TIP_CUT` toggle in `AdaptiveScalingOneAxisMotionTests.cpp` (gate S5) stays until the A/B has run; its removal is a separate WAIVER commit.
