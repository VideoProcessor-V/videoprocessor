# CutFadeJudge (shared unit U7, `VpUnit::CutFadeJudge`)

The one cut / fade / flash decision (doc 62, section 1.2 U7): `CutFadeJudge.h` + out-of-line `CutFadeJudge.cpp` (`VideoProcessor-Lib`), `kUnitVersion = 5` (2: the U7-ACCURACY sequence cut law; 3: the multi-frame fade law and partial reset on fades; 4: the first-principles 576-cell spatial affine fade law with motion compensation, `CutTracker` fade-in-from-black emergence veto, and strict black-origin cut separation; 5: W23 Phase 4 derived D10 CPU speed-up + D4/D5/D6/D7/D8 fade & veto upgrades — zero new arbitrary constants, all 5 GLSL kernel fragments untouched byte-for-byte). Bill's SceneDetector stays the Original pathway and is untouched.

- `ClassifyEvents` (unit version 5): two P4 records -> cut / "cut possible" / fade / flash (optional `AlignedPairCache*` reuses the `kShiftRadius` alignment and adjacent `FitGridFadeAligned` in `FoldFadeRun`); when P4 32 x 18 grids are present the pair fade decision uses `AlignGridGuarded` + `FitGridFadeAligned`, requires aligned interior mean-sign agreement (`stepMean * dir > 0`), sparse-only `FootprintPreserved`, `|1 - gain| < 1 / kFadeMaxDiv`, and `HighlightScalingConsistent` (with single-pair clipped-white drop floor `kFadeResidualReduction / kFadeMaxDiv` = 0.125). Gridless records (< 32 x 18 or synthetic) fall back to the M4 `(mean, spread)` pair law. `StrengthOf` maps it to the Indicator strengths (FULL = cut, MINOR = cut possible).
- `ScorePair` / `CutTracker` (unit version 2 T2 sequence cut law + unit version 4/5 fade-in-from-black veto, D6 & D10): the cut over the P4 32 x 18 cell grids of frames k-4 .. k+1 (a local-motion-tolerant residual spike against its temporal context, structure kept = a lighting change, a return at k+1 = a flash, and in v4/v5 an emergence from flat dark `prev` where `prev -> k` brightens monotonically within `kFadeMaxStepCodes` and `k -> k+1` is a verified 576-cell brightening affine fade with emergence gain `>= 1.0 + 1.0 / kFadeMaxDiv` = 1.25 = fade-in, not a cut; D10 skips `FitGridFadeGrid(k, k+1)` only when `k+1` is already scored with exact `G == 0.0`); one frame late, provisional without k+1; no grid: the pair law (counted). Its thresholds and the `U7CutTruthGateTests` gate (recall and precision >= 99.5 %, zero cuts on pan / flash / fade) are preserved.
  - **D6 Provisional-Cut Consumer Audit:** zero production consumers (`FillScene`, `DetailPulse`, `TextureRestore`, `TemporalDetail`, `AdaptiveDownscale`, `LedMeasurement`/`LedLookahead`, `ContentIntent`/`IntentInterpreter`, `CameraExtension`, `MotionValidity`) act on provisional (`!confirmed`) cuts; withdrawals when a provisional cut becomes `!cut` on confirmation are counted visibly via `SceneCounters::provisionalCutWithdrawn` and printed on the `Ctrl+Alt+D` `"Skeleton scene:"` line.
- `FadeRun` + `FoldFadeRun` (unit version 5, 576-cell spatial affine fade law with unit version 3 gridless `(mean, p99)` fallback): the caller keeps one `FadeRun` per stream and folds every pair in order; the frame's fade = the pair law's fade OR the run's.
  - **D10 CPU speed-up (decision-identical to v4 `AlignGrid` / `FitGridFadeAligned`):** direct integer indexing with precomputed zero-mean `cur` (`InteriorCurStats`) and lazy L1 evaluation in `AlignGrid` Step 1a, hoisted constant-offset bilinear stencils (`HoistedBilinear`) and carried Gauss-Newton state in Step 1b, shared `AlignedPairCache` between `ClassifyEvents` and `FoldFadeRun` (`LaneCpuProducts.h` + `SceneRunBefore`), and out-of-line `CutFadeJudge.cpp` (~9.4x-12.0x `SceneRunBefore` 7+1 rebuild speed-up, zero heap allocations).
  - **D5 motion-tolerant & boundary symmetry:** `AlignGridGuarded` holds `(0, 0)` when `>= kFadeSpatialCoverage` (50 %) of lit cells are stationary (`|cur - ref| <= kFadeCellStepEps`). Rigid `FitGridFadeAligned` runs first with sparse-only `FootprintPreserved` (`litCells < kFadeMinLitCells` = 98: zero collapse to black, `R^2_delta > kFadeSpatialConsensus` = 75 %, and `>= 75 %` two-sided cell scaling uniformity; full-picture `>= 98` passes through directly). When rigid fails or stalls from non-rigid OLS attenuation bias (without an explicit `FootprintPreserved` rejection) and `run.pairs >= kRefFrames` (4), `FoldFadeRun` falls back to `FitMotionTolerantFade` (Part A: 392-cell order-statistic OLS with `litCells >= kFadeMinLitCells`; Part B: exact `4 x 2` square `7 x 7` macro-tile `> kFadeMinSpread` displacement, `>= 75 %` consensus & coverage, `>= 75 %` per-tile affine uniformity, and `vFadeTile < kFadeResidualReduction * vIdTile`; Part C: `14 x 7` `2 x 2`-pooled Pearson correlation `>= kSameStructure` = 0.4, exempted only when `nearBlackFall && dir < 0 && gain < 1 / kFadeMaxDiv`). Also syncs `FadeRun::midP99` across pan leapfrogs and adds near-black fade-out `e.cut` symmetry (testing `base -> cur` and `prev -> cur` affine fade-out when `activeFade && dMean < 0 && cur.mean < kBlackMeanMaxP4`).
  - **D4 step continuation (`StepStillMoving`):** Neyman-Pearson Bayes likelihood-ratio strict majority `sSameEps > sOppEps` on above-half-LSB cells (with `sSameZero > sOppZero` when `|stepMean| <= kFadeCellStepEps || sSameEps + sOppEps == 0`, hoisted pinned-ceiling-excluded `stepAQ` sign consistency, and `4 x 2` macro-tile `>= 75 %` hold-dipole filter scoped to near-stationary holds `|stepMean| <= kFadeCellStepEps && |stepAQ - 1| <= kFadeScaleEps`).
  - **D8 false-fade reduction & D7 near-black re-seed symmetry:** `HighlightScalingConsistent` enforces raw-pixel `p99` scaling consistency about implied black (ITU-R BT.709-6 studio peak white `kStudioPeakWhiteCodes = 235.0` clipped-white fade-out censorship within 1-code quantization jitter `cp <= rp + kFadeMinSpread` and drop `>= 1 / kFadeMaxDiv` for runs or `0.5 / kFadeMaxDiv` for single-pair `ClassifyEvents`; reciprocal `[0.5, 2.0]` brightening bound; `>= 0.5 * |1 - gain|` darkening bound). Abrupt contrast jumps require the conjunction of raw spread jump (`aSpread * kFadeMaxDiv >= ...`) and hoisted whole-frame quantile jump (`stepAQ`), with time-reversal-symmetric `nearBlackRise` (D7: bounded near-black fade-in re-seed losing at most 1 frame after a failed black-origin reset) and `nearBlackFall` (active near-black fade-out collapse) exemptions, plus strict `k < run.keep` cumulative progress (`anchorKeep` / `midAnchorKeep`).
  - **D1 physical honesty (`tos` 2040/2041):** `tos` frame `2040/2041` is an abrupt VFX snap out of non-flat dark (`F(2039) = 0.0514`, 46 darkening cells, `spread 1 -> 180`, `S = 0.02`, `2040 -> 2041 A = 0.999`). Zero clip-tailored hacks were added; the `{2041}` pin awaits Owner Option (b) truth review (`U7-TOS-2041-VFX-CUT`).
  - Across near-black boundaries, unstructured black-origin continuation requires `prev` to be near-flat (`spread <= kBlackSpreadP4 || Flatness < kFlatF`) and `cur` to still be flat black (`spread <= kBlackSpreadP4 && Flatness < kFlatF`); once `cur` is textured, only a verified 576-cell affine fit can continue, preventing hard cuts from black from ever being co-labelled as fades. Gridless records (< 32 x 18 or synthetic) retain the v3 `(mean, p99)` linear fade-run fallback. A run continues only from the record it ends at (`FadeRunEndsAt`), so a skipped frame or restarted numbering starts a new run. Producer: the skeleton's scene product (`SkeletonModule::SceneFactsOf`, a ring of the run per frame, rebuilt from the lane's older P4 records when an entry is missing; a rebuild with reduced evidence and rebuild timing are counted and shown).
- Partial reset on fades (unit version 3, refined in unit version 4 with the spatial OLS gain `min(fit.gain, 1 / fit.gain)`; owner 2026-11-15 09:20, refs\102b U7-FADE-NO-HARDRESTART): a fade is NOT a restart. `FadeRun::keep` = min(gain, 1 / gain) of the run about its fitted black, never rising inside a run; `FoldFadeRun(..., &frameKeep)` gives the frame's step (keep after / keep before). `PairFadeKeep` = the pair law's spread ratio (min / max of p99 - p01). `FrameFadeKeep` = the smaller factor of the laws that called the frame a fade, 1 on a frame that is no fade. The product over a fade is the contrast the pre-fade picture still explains (a fade to black: 0), so consumers that multiply their history by it each frame shrink it monotonically and carry no pre-fade detail into the new scene. Amplitude domain; energy holders apply its square. No frame count, rate or window: the measured contrast change of the frame. Published as `FrameAnalysis::Scene::fadeKeep` (< 0 = not given: a consumer then falls back to the full restart, visibly). A full restart stays for the delivered cut only.
- Soft reset rule (C5 batch B, `cut_soft_reset`; additive, no output of the unit changes): `SoftResetStrength(confirmed, candidate, cut, flash, fade, strength)` = the strength when the CONFIRMED verdict is a candidate that is neither cut nor flash, the frame is no fade frame, and `strength >= kSoftResetBar`; else 0 (below the bar: no reset). `SoftResetKeep(s)` = 1 - `kSoftResetDepth` x s, the history keep a consumer multiplies by (amplitude). `kSoftResetBar` = 1.0 and `kSoftResetDepth` = 0.5 are PROVISIONAL pending the D8 truth run. With the T2 strength min(1, L / bar_T2), every spike candidate has strength 1, and the only candidates that are neither cut nor flash are those vetoed by "no cut right after a flash"; so at bar 1.0 only such a veto whose residual fully passed the spike bar fires. Consumer: `SceneRestart.h` (detail pulse, texture restore).
- `GridHistCut` + `MeanAbsDifference`: the HDR veto detector's rule; its thresholds (`kGridDifference`, `kHistogramDistance`, `kHistogramDistanceAlone`) are the single source and `HdrVetoCutDetector` aliases them.
- `FadeFit`: CPU twin of the matcher's M4 fade law with its switch in `FadeParams::enabled`. The law's numbers are named constants (`kFadeMinStepCodes`, `kFadeMaxStepCodes`, `kFadeMinBlack`, `kFadeMaxBlack`, `kFadeScaleEps`, `kFadeGain*`, ...); the matcher takes its per-frame step window from `FadeParams` (scaled to the measured source rate, never a literal rate).
- GLSL (moved byte-for-byte from the consumers; the consumers splice or dispatch the unit's text): `FadeKernelHeader` / `FadeKernelBody` (the matcher's M4 fade test, `DejudderWarp.cpp`), `TrustCutRegionalLine` / `TrustCutPlainLine` (the matcher's frame-trust cut; the histogram sweep it reads is `SourceStats::CoarseHistBody`, U6), `MeanStepCutLine` (formerly AdaptiveDownscale's scalar-pass cut; NO consumer since FIX-X5-CUT-P4; kept while `SharedUnitsW1Tests` and the shared-units baseline still reference it, retirement to be recorded as a 102b row). ## Design goal, philosophy and decisions
- One cut / fade / flash judgement for every consumer (00-UNIVERSAL rules 1 and 20; doc 62 s1.2 U7). Consumers adapt to it as a registered fix with an owner before/after table (lead8\FIX-B6-D8.md), never a private variant.
- Derived U7 v5 upgrades (W23 Phase 4 Track 1B; zero new arbitrary constants, all 5 GLSL kernel hashes unchanged): moves heavy non-template CPU bodies into `CutFadeJudge.cpp` (`VideoProcessor-Lib`) with 9.4x-12.0x decision-identical D10 CPU speed-up (`InteriorCurStats`, `HoistedBilinear`, `AlignedPairCache`, `CutTracker` `G == 0` fast-skip); adds motion-tolerant `FitMotionTolerantFade`, `AlignGridGuarded`, sparse-only `FootprintPreserved`, `HighlightScalingConsistent` (with ITU-R BT.709-6 `kStudioPeakWhiteCodes = 235.0` clipped-white censorship), Neyman-Pearson `sSameEps > sOppEps` step continuation, `aSpread && stepAQ` abrupt jump conjunction with `nearBlackRise`/`nearBlackFall` symmetry, and D6 emergence gain `>= 1.25` + visible `provisionalCutWithdrawn` telemetry.
- 576-cell spatial affine fade law, unit version 4 (owner ruling 2026-11-22 16:53 EST; zero fitted constants): upgrades both pair and multi-frame fade detection on P4 32 x 18 grids from the 2-scalar `(mean, p99)` model to motion-compensated global OLS affine regression (`cur_aligned ~= A * ref_aligned + c`) with elementary textbook ratios (`kFadeResidualReduction` = 0.5, `kFadeSpatialConsensus` = 0.75, `kFadeSpatialCoverage` = 0.5, half-LSB `kFadeCellStepEps` = 0.5 code), eliminating false fades on local occlusions, camera tilts across gradients, and animated graphics while preserving pan + fade detection via rolling sub-cell alignment. Also adds a first-principles fade-in-from-black emergence veto in `CutTracker::Judge` (reusing `FitGridFadeGrid` + `kFadeMaxBlack` + `kFadeCellStepEps`) and requires `curNearBlack` on unstructured black-origin continuation so hard cuts out of black cannot be co-labelled as fades. Gridless records (< 32 x 18 or synthetic) retain the v3 `(mean, p99)` fallback.
- Multi-frame fade law, unit version 3 (2026-11-15, after U7-ACCURACY's version 2; source: refs\102b row U7-MULTIFRAME-FADE-LAW and lead16\attrib-d8-t1b.md, D8_SyntheticFade on e06026518: the pair law fired on 12 of 56 slow-fade frames; owner D8 target agreement >= 99.5 %, SceneMissing 0, owner-decisions 671/673 as cited in lead15\opus-audit-L-B6.md). Evidence is the accumulated gain of a monotone run, so no frame rate, fade length or window length enters (00-UNIVERSAL rule 6); the black window and the two-pair minimum are FadeFit's (M4) own. Hard cuts are unchanged. Owner ruling 2026-11-15 (relayed by lead 16, lead16 review-u7fade.md): the D8 target is agreement with the TRUTH (real cuts and fades), not with the retired private judges. Derivation and per-clip expectation: lead16 handover folder, file u7fade-report.md.
- Partial reset, unit version 3 (owner 2026-11-15 09:20: "PARTIAL reset on fades (no full restart mid-fade; history gently reduced so pre-fade detail is not carried into the new scene)"; 08:35: high firing bar, precision first). The reduction curve is the simplest principled one: the contrast ratio the laws already measure, multiplied per frame. Owner before/after table: lead18 handover folder, file c5-fix-u7fade.md (an owner question: the curve itself).
- Soft reset bar (owner 2026-11-15 08:35 EST, question window U7 Q4, refs\owner-decisions-2026-11-07.md: "need the bar fairly high here. Mid scene firing is a major problem and the motion vectors correct themselves fairly quickly even without a reset. The threshold for firing should be high and we need to make it as accurate as possible."; plan lead19\c5-softreset.md items 1-4): precision first. One named bar in this unit (no consumer keeps its own), set as high as a strength goes (1.0) until the D8 / U7DIAG truth run measures the soft resets on and off the labelled cuts (D8PARTIAL "soft" fields: soft resets, at / off truth cuts, mean graded strength on non-cut frames, eligible frames at or above 0.5 / 0.75 / 0.9 / the bar). A lower bar needs zero soft resets off the labelled cuts on the cut-free rows and the owner's look at the proposed value and its false-fire count. A provisional verdict never fires (it never delivers a cut either). Fades keep their own partial reset, unconditional.

## Status and fallbacks
No downgrade of its own. The Original (Bill) SceneDetector remains available as the original authority. Consumers' downgrades (all visible): a fade group without `fadeKeep` (a producer before v3) is a full restart in detail_pulse_stabilise / texture_restore (their "scene judge" fallback entry, `SceneFadeWithoutKeepWhy`) and in temporal detail ("reset: fade (no keep)"); a fade run rebuilt with reduced evidence is shown on the skeleton's "Skeleton scene" line.
